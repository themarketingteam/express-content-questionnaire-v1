# Express production release audit — November 14, 2026

This release adds the Q2/Q8 page organizer and hardens the actual hosted persistence and recovery paths. Legacy arrays/Other fields remain, organized questions export compact two-level trees with the version marker, and drafts retain editor IDs. Express limits remain 3–6 service pages and 1–3 industry pages.

## Data and concurrency protections

- Saves, clears, and submissions use confirmed server snapshots. Failed/ambiguous clears preserve visible answers. Delayed validation and pre-clear requests cannot restore older answers.
- Renewable entity leases use token/expiry fencing for draft updates. Drafts are reloaded and authorized after acquiring the lease; finalized snapshots cannot be changed by old retries.
- Submission waits for the reviewed snapshot to be acknowledged. Null, stale, finalized, malformed, or inconsistent acknowledgments cannot become a successful save.
- Duplicate checks fail closed when unavailable. Final and recovery receipts are verified against raw answers, transformed payload, flattened fields, identity, and version before acknowledgment/redelivery.
- Historical duplicate-session rows are preserved. An exact authorized draft can be selected using its ID and recovery key; genuinely ambiguous records require review. No automatic merge or deletion is performed.
- Existing remote entity names and answer-field types are preserved. Additions are optional. Existing baseline retention permissions and scheduled automation settings are retained.

## Verification and rollout

The final storage-contract follow-up passed 248 Node tests, full lint, frontend TypeScript, and a strict cached Deno check for all nine critical changed backend paths and their shared imports. See [backend verification](validation/BACKEND_TYPECHECK.md). Production module-graph checks reject local adapters; a build proof records the app ID, source commit, and final asset hashes. Deployment requires the clean canonical GitHub main commit and that matching production build.

The first isolated live check reproduced Base44's entity-read hydration: optional typed node properties appear as null IDs and empty child arrays even when the serialized payload is compact. A dedicated stored-record reader now removes only those known placeholders before receipt comparison, recovery, or PDF conversion. Raw editor snapshots and new incoming/outbound payloads keep their strict validation. Actual raw answers and serialized submitted payloads were preserved throughout; no webhook was invoked by the failed synthetic check. The regression suite reproduces this platform behavior rather than assuming an exact in-memory entity echo.

Current deployed function source, entity schemas, and available public static assets were backed up outside the repository under `/Users/isaachines/.codex/backups/questionnaire-release-20261114/express`. No entity or field is scheduled for removal. Schema/functions are deployed before the frontend. The prepared [live persistence smoke script](../scripts/base44/live-persistence-smoke.ts) creates one clearly marked random synthetic session and verifies save/reload/clear/restore, compact final persistence, idempotent retries, and finalized-save holds. It never invokes a delivery/email function and never modifies real client rows. Successful synthetic audit rows remain for traceability.

## Boundaries

Cross-entity creation and receipt linkage are separate platform operations. External webhook delivery is also separate and retains its existing acknowledgment/retry semantics; this release does not claim transactional exactly-once external delivery. The running Zapier workflow is not reconfigured. Organized payloads keep their legacy projections so existing consumers can continue reading their current fields.

Browser bootstrap now also tolerates browsers that deny access to the localStorage property itself; published endpoint pinning and recovery hashes remain intact.
